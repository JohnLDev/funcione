# Workout Execution Control Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a frontend-only workout execution control that lets users start a training session, mark completed items, finish with pending items, and see a positive sport-themed completion modal.

**Architecture:** Keep `TrainingActivePlan` as the plan surface, but split execution-specific state and UI into focused helpers/components. Store in-progress execution state in `sessionStorage`, scoped by user/plan/session, and preserve the existing training item details in both regular details and execution control. No backend or API contracts change.

**Tech Stack:** React, TypeScript, Vite, Tailwind CSS, react-i18next, Playwright E2E, browser `sessionStorage`.

## Global Constraints

- Work on branch `codex/workout-execution-control`; do not push directly to `main`.
- Shell commands must run with `rtk`.
- Use TDD: write failing E2E before production code.
- Preserve current active plan structure and all item details.
- Use `sessionStorage`, not backend persistence.
- Do not change REST contracts, database migrations, or OpenAPI.
- Keep mobile-first layout without horizontal overflow or clipped text.
